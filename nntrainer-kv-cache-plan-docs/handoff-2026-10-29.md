# 작업 인계 — 2026-10-29

## 상태

**요청한 후속 작업의 로컬 구현·검증·측정 완료.** 토큰 한도로 중단한 상태가 아니다.
실행 중인 모델/측정/기기 작업은 없다. 다음 GPU adapter 구현은 시작하지 않았다.
이 파일은 사용자의 “잔여 토큰이 5% 이하이면 별도 파일에 기록하고 중단” 지시에
따라 진행 중부터 유지한 체크포인트를 완료 상태로 갱신한 것이다.

## 목적과 변경

사용자 순서: 성능 기준 확보 → 경계/반복 검증 → 필요한 최적화 → CPU 단계 마감
→ 다음 backend 조사/선정. 외부 리뷰의 CI/실행 연결/성능/커버리지 지적을 반영했다.

- CI changed-line clang-format14와 level1 Doxygen 누락을 재현·교정.
- CPU runtime 선택 helper 및 layer snapshot 통합. ARM tiled packing을 기본에서
  `NNTR_CPU_KV_TILED=1` opt-in으로 복구. `NNTR_CPU_KV_LEGACY=1` 호환 storage 검증.
- core checked view를 실제 MHA 쓰기·읽기에 연결. producer가 완료를 직접 통지하며
  facade의 graph 종료 후 일괄 markReady 제거. 누락 producer는 commit 실패.
- CPU facade ring, managed incompatible layout을 명시 거절. scope가 끝난 access도 거절.
- hybrid non-attention block 선언, LFM2 wrapper/pool release 연결.
- tiny adapter를 실제 wrapper로 변경, 실제 Qwen/LFM graph 부정·경계·반복 회귀7 추가.
- 타이밍 전용 runner와 header/runtime ABI 페어링, explicit serial, 안전한 runtime freezer.
- GPU/NPU 공유·KV 양자화·전체 모델 상태 rollback은 구현했다고 주장하지 않는다.

## 성능 결과와 해석

Q4 weight, context1024/4096, activation plane128, prefill chunk128, decode32,
threads4/BLAS1. 10process = warmup10 + measured50회.

- Linux 후보1K latency 변화 run+0.36%/prefill+0.58%/decode+0.26%.
- Linux 후보4K는−1.29%/−1.22%/−2.48%. 동일조건5% budget 충족.
- Android1K는+1.17%/+1.08%/+1.82%, budget 안.
- Android 최초4K run31.170→34.300s(+10.04%) gate 실패 보존.
  baseline 자체가 반복 중28.167→34.358s로 느려짐.
- heated 역순 baseline34.817s 대비 후보34.300s(−1.48%)로 최초 회귀 미재현.
  열·실행순서 영향을 통제한 일반적인 속도 개선으로 주장하지 않는다.
- tiled4K 관측 run29.131s/peak model memory931472KiB, packed980340KiB보다 낮음.
  시작 온도가 달라 인과적 speedup/일반적인 RSS 감소로 해석하지 않는다.
- 모든4K는128token씩32forwards이며 단일 unchunked4K가 아니다.
  FP32 weight 성능, 타일 sweep, hardware copy traffic은 이번 미측정.
- 기본값은 기존 packed 유지, tiled는 선택 가능한 memory/latency 실험.

전체 결과: `build-kv-perf/performance-summary.json`,
`performance-checkpoint.json`, [성능 기록](cpu-performance.md).

05 · Glossary

Every acronym and project word used in this guide, one line each. Where a term has a precise definition in the project, the section is given.

Hardware and platform

DSP
Digital signal processor: a second processor in the phone built for wide vector math and low power.
cDSP
The compute DSP of a Snapdragon chip, the one this backend runs on (HEXAGON.md §1).
Hexagon
Qualcomm's DSP architecture and instruction set.
HVX
Hexagon Vector eXtensions: 128-byte vector registers and instructions; "HVX only" means no HMX (HEXAGON_BENCHMARK.md).
HMX
Hexagon Matrix eXtensions: a matrix unit (one per core) reachable through HexKL. Since #68 (PR #72, 2026-09-21) a skel built with the HexKL addon mounted acquires the HMX unit and a VTCM arena at init(), but no op uses it yet; stage 3 of the goals (issue #65) plans it for 4-bit weights (u8 activation × int4 weight), stage 2 (HMX for the A8W8 line) is deferred (HEXAGON.md §2.2, §9).
HexKL
Qualcomm's kernel library that exposes HMX; must be obtained from Qualcomm (plan 0000 §3) and is never committed (NOTICE). The add-on at /opt/qcom/hexkl_addon (HEXKL_ADDON_ROOT) carries libhexkl_micro.a; since #68 the build scripts link it whenever it is present (-DHTP_HMX=1), and the version read at init is 1.0.0-beta1 hexagon v79 (HEXAGON.md §2.2, §5.3).
HTP_HMX
The compile flag the build scripts set themselves: 1 when HexKL is on the mount (the hmx/ sources are compiled and HexKL linked), 0 otherwise or with HEX_EXTRA_CFLAGS=-DHTP_HMX=0 (the HVX-only tree, object-identical to before #68) (HEXAGON.md §5.3; build_skel.sh).
VTCM arena (HMX arena)
In an HTP_HMX build, the VTCM above the HVX kernels' unchanged first 4 MB: HexKL's config region at the top, two 8 KB int32 result tiles below it, the rest free for a future kernel's activation tiles and weight strips; 8 MB requested with the HMX unit, 4 MB floor (HEXAGON.md §2.2 "HMX arena"; hmx/htp_hmx.h).
acc layout (accumulator tile layout)
The undocumented arrangement in which HexKL lands a 64×32 int32 result tile in VTCM; hexkl_acc_tile.c (ported from PR nntrainer#4327) probes it with a ramp so a result can be read in place instead of through HexKL's slow vendor copy. Simulator: usable=1 base=0 row_stride=32; the one HMX fact the simulator cannot vouch for, re-read on the device in the first HMX handoff (HEXAGON.md §7 rule 11).
WH layout / WH bake
HexKL's weight-tile order for HMX: a 32×32 int4 tile (512 B) is permuted by rm_to_wh_i4 before use. #68's hmx test showed the bake is a pure bit permutation of the index — element (k, n) → byte 128·(k>>3) + 4·n + (k&3), nibble (k>>2)&1 — and that a baked tile survives a VTCM → DDR → DMA → VTCM round trip (HEXAGON.md §5.2, §7 rule 11).
v75 / v79
Hexagon architecture versions. The S25 Ultra's cDSP is v79; since #35 (2026-09-18) the shipping skel is built HEX_ARCH=v79, and a v75 build, which runs unchanged on v79 silicon, is the fallback (HEXAGON.md §7 rule 1, §9).
unit / serial
One physical phone, named by its adb serial. Two S25 Ultra units are on record, R3CY10WM83Y (1.91 GHz in the decode loop) and R3CY205ZMND (2.05 GHz); tok/s is compared only within a unit (HEXAGON.md §7 rule 9).
pcycles_per_us
The DSP's effective clock in MHz during a run, printed by the harness; read gaps and bars against it, not against the nominal 2090 (HEXAGON.md §7 rule 9 (c)).
SSR
Subsystem restart: the DSP crashing and rebooting; a real failure, unlike the benign adsprpc permission lines (23-sdk64-baseline.md "Notes").
8 Elite / SM8750
The Snapdragon 8 Elite chip of the Galaxy S25 / S25 Ultra (HEXAGON.md §8).
VTCM
Vector Tightly Coupled Memory: small, fast memory local to the DSP; 4 MB requested best-effort (HEXAGON.md §2.2).
DMA
Direct memory access: an engine that copies memory (DDR → VTCM) while the vector unit computes.
DDR
The phone's main memory, shared by CPU and DSP.
QuRT
The real-time OS on the DSP; provides threads, HVX locking and the simulator boot image.
PD (unsigned PD)
Protection domain, a process on the DSP; "unsigned" avoids per-device signing (HEXAGON.md §1.2).
pcycles / Mcyc
DSP processor cycles as counted by HAP_perf_get_pcycles; Mcyc = millions of them per token. Mcyc per decode step is the number to compare across device units (HEXAGON_BENCHMARK.md "Method").

RPC and memory

FastRPC
Qualcomm's remote procedure call between CPU and DSP; one call per chunk or token here (~0.26 ms).
IDL
Interface definition language; nntr_htp.idl declares init, forward, forward_debug.
QAIC
The SDK tool that turns the IDL into a stub and a skel at build time.
stub / skel
Generated glue: the stub runs on the host and marshals the call, the skel runs on the DSP and unmarshals it. "The skel" also names the whole DSP library libnntr_htp_skel.so.
rpcmem / dma-buf / fd
Shared memory both processors can address, allocated by RpcmemBuffer, identified by a file descriptor (fd) and handed to the DSP once (HEXAGON.md §1.1).
HAP_mmap
The DSP call that maps a registered fd for the session.
AEE codes
The DSP error numbers (AEE_EBADPARM, AEE_EUNSUPPORTED, …) from AEEStdErr.h. The DSP returns them as-is (HEXAGON.md §1.3); FastRPC hands them to the host offset by the 0x80000400 DSP error base, which is why logs show 0x80000406 / 0x80000414 (hexagon_runner.cpp).
AEE_EBADPARM
"Bad parameter", code 14: what init() returns for a rejected op-list (every validator rc but 3) and forward() for a bad token count, position, logits length or token id. Seen on the host as 0x8000040E, spelled kHexagonBadParm in hexagon_runner.h so the host-side token-id pre-check can return the identical value (HEXAGON.md §1.4).
ABI
Application binary interface; here the op-list wire format, version 4 (HEXAGON.md §1.4).
op-list
The 64-byte header plus 64-byte op descriptors that tell the DSP what to run.
WEIGHTS / KV / ACT / TOKENS / LOGITS
The five buffer ids an op can reference; the first three are mapped once, the last two are per-call arguments.
FARF
The DSP logging macro; lines reach logcat only with a .farf level file (HEXAGON.md §5.3).
SSR
Subsystem restart: the DSP crashing and rebooting.
adb
Android debug bridge, the USB command line to the phone; used only by the person with the workstation.

Model and numerics

LLM, decoder-only
A language model that generates one token at a time from the previous ones; Qwen3-0.6B here.
prefill / decode
Prefill processes the prompt in chunks (128 tokens by default); decode generates one token per call.
tok/s
Tokens per second; prefill and decode are reported separately because they have different bottlenecks.
logits
One score per vocabulary entry for the next token; 151,936 floats for this model.
PPL
Perplexity: how surprised the model is by a known text, lower is better; measured teacher-forced with --eval.
top-1
How many next tokens the model's best guess got right during --eval.
teacher-forced
Feeding the true next token instead of the generated one, so every step is comparable.
W8A8 / W8A16
8-bit weights with 8-bit (or 16-bit) activations; the activations are quantized per token on the fly.
W8_CX
The checkpoint format: int8 weights with one fp32 scale per output channel (per-channel, "CX").
RTN (round to nearest)
The plainest weight quantiser: scale = amax ÷ 7 per output channel, each weight rounded to the nearest int4 code. #65 S1's x86 result (in review) is for per-channel int4 RTN on Qwen3-0.6B: PPL 46.2279 / 148 against W8's 22.5282 / 186, 2.052 × (HEXAGON.md §8.1 on branch hvx/69-w4cx-producer-abi5).
per-token / per-channel
One scale per activation row (token) / one scale per weight output row (channel).
tiled32
The weight byte order: 4 KB tiles of 32 rows × 128 k, so one vector holds 32 rows × 4 k (HEXAGON.md §2.1).
vrmpy / vrmpyacc
The HVX instruction that multiplies 4 int8 pairs per lane and accumulates into int32 lanes.
MAC / GMAC
Multiply-accumulate operation; billions of them.
KV cache
Stored keys and values of every earlier position so decode does not recompute them; lives on the DSP.
GQA
Grouped-query attention: several query heads share one key/value head (16 share 8 here).
SDPA
Scaled dot-product attention, the score-softmax-mix computation.
RoPE
Rotary position embedding, applied to q and k from a precomputed cos/sin table.
RMSNorm / QK-Norm
Root-mean-square normalisation; QK-Norm applies it per head to q and k.
SiLU / SwiGLU
The activation function and the gated block (SiLU(gate) ⊙ up) in the feed-forward part.
down_proj
The last feed-forward matmul, fed by the SwiGLU output; the one with int16 activations.
lm_head
The final projection to logits; tied to the embedding table here.

Float formats and precision words

fp16 / fp32
16- and 32-bit IEEE floating point; hf and sf in HVX instruction names.
qf16 / qf32
Qualcomm's intermediate float formats on HVX; converted back with _equals_ instructions (HEXAGON.md §7).
IEEE-format ops
HVX instructions that operate directly on fp16/fp32 (Vhf_vadd, Vsf_vmpy, …); avoided by rule 1.
RNE
Round to nearest, ties to even.
Von Neumann (jam) rounding
qf32's truncate-and-set-LSB behaviour, why the quantizer needs a magic constant (HEXAGON.md §7 rule 6).
ulp / LSB
Unit in the last place / least significant bit: the smallest step of a number format.
atol / rtol
Absolute and relative tolerance in |d| ≤ atol + rtol·|ref|.
rel-RMS
Root-mean-square of the difference relative to the reference, over a whole tensor.
splat
Broadcasting one value into every lane of a vector.
epilogue
The part of a matmul kernel after the integer sums: scaling and narrowing.

Tools and files

SDK
Hexagon SDK 6.4 (6.4.0.2 in the container, 6.4.0.1 on the workstation), with hexagon-clang 19.0.04 (toolv19).
NDK
Android NDK r26d, baked into the dev image, cross-builds the host harness.
qpm-cli
Qualcomm Package Manager; installs the SDK inside the container after a login.
OrbStack / Rosetta
The container runtime on the Mac and Apple's x86 emulation the simulator runs under.
hexagon-sim
The instruction-level simulator; correctness gate, no DDR model.
test_hmx / hmx
The 14th simulator test since #68, built only with HTP_HMX=1: acquires VTCM + HMX, probes the acc layout on worker 0 under the lazy lock, runs one 64×32 u8 × 32×32 i4 micro-matmul against a scalar int32 reference, relocates a baked WH tile through DDR and prints the WH permutation. Without HexKL it prints SKIP: built without HTP_HMX and returns 2, never a pass (HEXAGON.md §5.2).
dsp_obj_md5.sh
Compiles each skel source with -c under the same flags as build_skel.sh and prints a sorted md5 list — the per-object proof that a PR changed no DSP bytes; the linked .so embeds random temp object names and is never comparable (HEXAGON.md §3; skill hexagon-gates).
SIM_TEST / SIM_PROF / STAT
Line prefixes of the simulator tests, the profile scenarios and their recorded statistics.
E2E / RPC_TEST
Line prefixes of hexagon_e2e_test and hexagon_rpc_test on the device.
.hexw / .hexcfg
The packed weight image and its 12-line shape file (HEXAGON.md §2.4).
.i32
A token file: 32-bit little-endian ids from make_tokens.py.
md5
A checksum used to prove which artifact actually ran.
HF
HuggingFace; the public Qwen3-0.6B download the wizard fetches.
GENIEX / QAIRT / QPN
Qualcomm AI Hub runtimes (GENIEX_LLAMACPP = llama.cpp under Genie, GENIEX_QAIRT = a QNN graph) and reference platform (QPN) whose rows are the references in HEXAGON_BENCHMARK.md: the LLAMACPP q4_0 NPU rows give the w4a8 goals 70.3 / 27.5, the QAIRT w4a16 Galaxy S25 rows (8,207 / 121, 7,503 / 112, 3,546 / 57.6) are the stage-3 (#65) reference. All of them are in the "Baselines and references" table on 06.

W8A8 / w4a8 / w4a16 / q4_0 / Q4_0-FP16 / w4cx
Weight and activation bit widths: 8-bit weights with 8-bit activations (this backend); 4-bit weights with 8-bit activations (the stage-1 w4a8 goal row and the #65 port); w4a16 and q4_0 are the Qualcomm AI Hub rows' formats; Q4_0-FP16 is the precision of nntrainer's own CPU baseline (4-bit block-quantised weights, fp16 activations; issue #60); w4cx is #65's per-channel int4 image layout — one fp32 scale per output channel, the only form HMX's u8×i4 tiles can apply; its x86 accuracy on Qwen3-0.6B (S1, in review) is 2.05 × the W8 PPL, far outside the ≤ 1.10 × gate, and the format is pending a user decision (HEXAGON_BENCHMARK.md; plan 65 §3, §4; HEXAGON.md §8.1 on branch hvx/69-w4cx-producer-abi5).
weight-stream bound / ceiling
The decode ceiling set by reading every weight byte once per token: 596 MB of int8 weights per step. Measured in #25 with a stream-only skel: 32.3 GB/s, 54 tok/s at 512 (≈ 54–57 at every depth); the provisional ≥ 60 goal was withdrawn as above it, and 70.3 with int8 weights would need 41.9 GB/s (HEXAGON_BENCHMARK.md "Goals" and ceiling row; issue #49).
cross-op prefetch
Each tiled matmul kicks the first DMA chunk of the next tiled matmul into its free VTCM half while the small ops in between run; one DMA queue per worker for the session. −11.6 % decode cycles at 512 in #25, on by default; on hvx_impl since PR #61 merged (HEXAGON.md §2.2).
stream-only skel (HTP_MM_STREAM_ONLY)
A measurement build that DMAs every weight byte and multiplies nothing; outputs are garbage, its step time is the ceiling (#25 variant C).
HTP_PROF_FARF / summ_farf_prof.py
A measurement build flag that makes the DSP print, per forward call, its cycles split into mm8 / mm16 / lg / attn / rest; the script takes the decode medians of a device_farf_*.log (on hvx_impl since #25 / PR #61; the attn column is what #58's gate reads).
CPU baseline (#60)
nntrainer running Qwen3-0.6B on the S25 Ultra CPU from main at Q4_0-FP16 (user decision 2026-09-18); every NPU goal is a multiple of it, written as the multiple plus the resolved tok/s once measured (pending; handoff on branch hvx/60-cpu-baseline).
cold run / reversed double pass
The first e2e run after a push is slower (3–5 % in #24, +8.5 % DSP cycles in #25); any A/B verdict tighter than ±10 % is run twice with the order reversed and only the second pass is read (HEXAGON.md §7 rule 9 (d)).
4096 A/B inside one order (rule 9 (e))
At 4096 even the DSP Mcyc figure moves with the session (±5 % between sittings on one unit, ≈ +9 % between units with the same binary; #53), so a 4096 verdict compares both skels back to back inside one order after the same idle, with battery °C and charging status recorded before the order; a 4096 cell is never read against another sitting's row (HEXAGON.md §7 rule 9 (e)).
sixth-worker simulator caveat
In the v79 simulator worker 5 of a six-worker pool runs at half the speed of workers 0–4 in every configuration (#58's per-worker timers), so a simulator op-total ratio over a balanced pool under-reads; the device decides (58-decode-attn-gqa.md "Notes from the run").
FASTRPC_MAP_STATIC
A FastRPC mapping flag that maps a host rpcmem buffer once for the session instead of per call; used for the logits buffer since #24 (HEXAGON.md §1.1, §8.2 "Host path"; on hvx_impl since PR #52).
handoff
A docs/measurements/<issue#>-<slug>.md file a person executes on the phone and fills in.
gate / rung
One level of the verification ladder in the hexagon-gates skill; rungs 0–4 in the container, 5 on the phone.
state:* labels
The issue state machine: needs-plan → planned → in-progress → review, with needs-measurement → measured on the side (plan 0000 §5).
engine="htp"
The nntr_config.json switch that sends the whole model to the DSP (HEXAGON.md §5.4).
fallback
The app running on the CPU when the DSP path is unavailable; a safety net, not a strategy.
harness
hexagon_e2e_test / hexagon_rpc_test: the standalone device programs used for measurement and debugging.
reference
hexagon_ref_run on x86, the accuracy oracle.

Appendix A. LFM2 benchmark results

The deployed LFM2 24B-A2B SR15 pack (TL2/INT4) was measured on November 4, 2026, on the same phone and runtime as the Gemma4 benchmark. Inputs are 1,024 / 2,048 / 4,096 / 8,192 tokens, with 128 output tokens per run. This appendix preserves those measurements.

LFM2 results

Each value is the median of three runs, with minimum–maximum in parentheses. The 1K warm-up is excluded; there are 12 measured runs.

Input tokens Prefill (tok/s) Decode (tok/s) TTFT (s) Peak memory (GiB)
1K (1,024) 799.4 (761.9–826.5) 18.60 (18.34–19.31) 1.30 (1.26–1.37) 2.146 (2.145–2.146)
2K (2,048) 1083.0 (1083.0–1084.8) 18.19 (18.04–18.33) 1.91 (1.91–1.91) 2.213 (2.213–2.229)
4K (4,096) 768.8 (766.0–769.5) 17.16 (17.11–17.16) 5.35 (5.34–5.37) 2.263 (2.263–2.267)
8K (8,192) 571.5 (566.6–574.4) 15.26 (15.19–15.29) 14.36 (14.29–14.48) 2.264 (2.264–2.266)

Native token traces confirmed the exact input IDs and 128 output IDs in every run, including the full 8,192-token input. Output IDs were identical across all three repeats at each length. Logs confirmed the resident NPU graph, including convolution, attention, MoE and LM head.

LFM2 model and conditions

Item Measured configuration
Device Galaxy S26 Ultra SM-S948U, Snapdragon SM8850, Hexagon v81, Android 16, 4 KB pages; the same phone used for Gemma4.
Runtime The CLI executable and all seven native libraries match the Gemma4 measurement by SHA-256. The libraries also match the installed Quick.AI app. Binary source commit is unverified; the archive identifies the measured artifacts by hash.
Model pack /sdcard/Download/aistudio-mobile/models/lfm2-24ba2b-htp-w4a32; lfm2_weight_format=sr15_v2, lfm2_execution_profile=htp_fused.
Weight file LFM2-24B-A2B-Ternary-INT4.bin, 5,433,850,513 bytes (5.43 GB). The full checksum is in manifest.json inside the archive.
Quantization Rotated TL2 experts (TL2CX_WH), affine INT4 projections/router/LM head (QS4CX_WH_AFFINE), Q4_0 embeddings and DW3_INT4 short convolutions.
Shared settings Batch 1, greedy decoding, eight CPU threads, moe_cache_experts=16, init_seq_len=2048, max_seq_len=8704.
LFM-specific settings LFM tokenizer/chat template, attention KV q8_row, EOS ID 7 and the automatic SR15 CLI preset are retained.
Prompt The same original report paragraphs and summary request as Gemma4, tokenized with LFM's tokenizer and padded to each exact length. Different tokenizers mean different text lengths at the same token count.
Repetition and cache One excluded 1K warm-up, then three fresh CLI processes per length. Pass order: 1K→2K→4K→8K; 8K→4K→2K→1K; 1K→4K→2K→8K. OS caches are retained.
Temperature USB connected; at least 15 seconds between runs. Start only at thermal status 0, AP ≤34 °C and skin ≤35.5 °C, matching the Gemma4 procedure. Recorded starting ranges: AP 29.4–32.8 °C, skin 29.4–32.0 °C.

The deployed pack's init_seq_len was 64. Only isolated benchmark copies raised it to 2,048, removed chat_input so the exact sample_input was used, and set num_to_generate=127, bad_word_ids=[7], greedy decoding and a token-trace path. The original model pack and app settings were unchanged. EOS suppression is for fixed-length measurement; retain the provider's stopping behavior for chat.

Reading the LFM2 measurements

  • Output count: one token selected during prefill plus 127 decode steps gives 128 total output IDs. The CLI's generation: line reports 127 tokens.
  • Speed: Prefill is input tokens divided by prefill time; Decode is 127 / generation_seconds, including the first decode step.
  • TTFT: native [PERF-SPLIT] ttft_ms, excluding process startup and model loading. It is not app launch-to-answer latency.
  • Peak memory: sampled RssAnon + accelerator, converted from KiB to GiB. File-backed page cache is excluded; this is not total phone RAM usage or weight-file storage size.

The workload measures throughput on synthetic report prompts. It does not measure model accuracy or sustained performance on a hot phone. Gemma4 and LFM2 differ in architecture, active parameter count, tokenization, KV format and execution preset, even though the measurement procedure is aligned.

LFM2 measurement records

Download the LFM2 summary JSON, individual runs CSV, or complete measurement records ZIP.

The ZIP preserves the November 4 records: raw CLI logs, exact prompts and expected IDs, native token traces, per-run configurations, thermal readings, binary/weight checksums and measurement scripts. It includes the excluded warm-up, marked separately in results.json and the CSV. Model weights and runtime binaries are not included. summary.json aggregates only the 12 measured runs.

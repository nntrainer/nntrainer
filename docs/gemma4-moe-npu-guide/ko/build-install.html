5. 네이티브 런타임 빌드 및 설치

먼저 빌드하기

호스트 PC에서 실행합니다.

cd "$NNTR_ROOT/Applications/CausalLM"
set -o pipefail
./build_android.sh --htp 2>&1 | tee "$NNTR_ROOT/gemma4-htp-build.log"

스크립트는 FastRPC stub 생성, v81 DSP 이미지 빌드, Android 엔진과 토크나이저 빌드, CausalLM 도구 빌드를 순서대로 수행합니다. DSP 빌드는 심볼과 아키텍처를 확인하며, 성공하면 ARCH OK (V81)이 출력됩니다. 마지막에는 산출물 디렉터리와 함께 Done (native htp build)가 표시되어야 합니다. pipefail을 켰으므로 tee로 로그를 저장하더라도 앞선 빌드 명령의 실패가 가려지지 않습니다.

산출물 NNTR_ROOT 기준 위치 용도
nntr_causallm builddir_app/htp/ 모델 팩을 직접 실행하는 CLI
quick_dot_ai_test builddir_app/htp/ C API 실행 및 선택적 수명 주기 테스트
libcausallm.so, libquick_dot_ai_api.so builddir_app/htp/ 모델 런타임과 공개 API
libnntrainer.so, libccapi-nntrainer.so builddir/android_build_result/lib/arm64-v8a/ nntrainer 엔진
libnntr_hvx_skel.so nntrainer/tensor/htp_backend/dsp/build/ v81 DSP 프로그램
nntr_quantize, nntr_safetensors_info builddir_app/htp/ 추가 도구. 이 양자화 도구로 해당 HTP 팩을 생성할 수는 없음

주요 실행 파일 두 개와 DSP 이미지를 확인합니다.

cd "$NNTR_ROOT"
ls -lh builddir_app/htp/nntr_causallm \
  builddir_app/htp/quick_dot_ai_test \
  nntrainer/tensor/htp_backend/dsp/build/libnntr_hvx_skel.so
file builddir_app/htp/nntr_causallm

CLI는 ARM aarch64 실행 파일입니다. x86-64 PC에서 직접 실행하지 말고 휴대전화에서 실행하세요.

휴대전화에 설치하기

ADB 승인이 완료된 휴대전화를 연결하고 호스트 PC에서 실행합니다.

cd "$NNTR_ROOT/Applications/CausalLM"
./build_android.sh --htp --cache --install
adb shell ls -lh /data/local/tmp/Quick.AI

--cache는 호환되는 엔진 빌드를 재사용하지만 나머지 빌드 단계는 수행합니다. --install은 실행 파일과 런타임 라이브러리를 /data/local/tmp/Quick.AI에 배포하고, 이 경로에서 스크립트가 관리하는 런타임 파일을 교체합니다. run_causallm.sh와 run_test.sh 실행 래퍼도 생성합니다. 모델 팩은 복사하지 않습니다.

런타임에는 HexKL의 libsdkl.so와 NDK의 libc++_shared.so가 포함됩니다. libcdsprpc.so는 휴대전화의 vendor 파티션에서 제공합니다. ARM 라이브러리, stub, DSP 이미지는 함께 빌드하고 배포하세요. 새 빌드에 오래된 DSP 이미지만 복사하면 서로 사용하는 프로토콜이 맞지 않을 수 있습니다.

--clean은 선택한 CausalLM 네이티브 빌드 디렉터리를 다시 만듭니다. 모든 엔진 및 Gradle 캐시까지 지운다는 의미는 아닙니다. HTP의 기본 CPU 스레드 수는 8이며 첫 실행에서는 그대로 사용하세요.

최신 스크립트의 --stage는 공개 네이티브 파일을 builddir_app_stage/public/htp/에 모으고 옆에 .manifest.json 보고서를 만듭니다. --stage=DIR로 지정한 전용 디렉터리는 실행할 때마다 다시 생성됩니다. 라이브러리를 다른 앱에 통합할 때 사용하는 옵션이며, 일반 앱 빌드는 자체적으로 파일을 준비합니다. --cache는 OpenCL 설정도 확인하여 호환되는 엔진만 재사용합니다.

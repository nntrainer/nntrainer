9. 벤치마크 결과

2026년 11월 4일 최종 배포된 회전 TL2 팩으로 새로 측정한 결과입니다. 설치된 Quick.AI 앱과 네이티브 라이브러리가 같은 CLI 런타임을 사용했습니다. 입력은 1,024 / 2,048 / 4,096 / 8,192토큰, 출력은 매 실행 128토큰입니다. 이전 PR의 과거 측정표를 아래 실측 결과로 교체했습니다.

같은 입력·출력 길이, 기기와 런타임으로 별도 측정한 결과는 LFM2 벤치마크 부록에서 확인할 수 있습니다.

배포 모델과 측정 조건

항목 측정에 사용한 설정
기기 Galaxy S26 Ultra SM-S948U, Snapdragon SM8850, Hexagon v81, Android 16, 4 KB 페이지.
모델 팩 /sdcard/Download/aistudio-mobile/ 아래의 models/gemma4-26b-a4b-htp-w4a32.
양자화 Expert는 회전 TL2(moe_layer_dtype=TL2CX_WH), projection과 LM head는 affine 4-bit(QS4CX_WH_AFFINE), embedding은 Q4_0입니다. 모델 전체가 동일한 TL2 형식인 것은 아닙니다.
가중치 파일 nntr_gemma4_26b_a4b_tl2_rotated.bin, 6,604,561,848바이트(6.60 GB). 전체 SHA-256은 측정 manifest에 기록했습니다.
런타임 네이티브 .so 7개의 SHA-256이 설치된 Quick.AI 앱과 모두 일치합니다. CLI 실행 파일의 해시도 기록했습니다. 바이너리의 소스 커밋은 확인되지 않았으므로 해당 배포 빌드의 측정값으로 해석하세요.
추론 HTP fused 실행, batch 1, greedy decoding, CPU 스레드 8개. Attention, projection, dense FFN, MoE, LM head는 HTP를 사용하며 매 실행 NPU resident graph를 확인했습니다.
컨텍스트·캐시 배포 기본값인 init_seq_len=2048, max_seq_len=8704, attention KV q8, moe_cache_experts=16, moe_decode_prefetch=true를 유지했습니다. 8,192토큰 입력도 잘림 없이 모두 처리했습니다.
프롬프트 여러 문단을 반복한 영어 보고서와 요약 요청입니다. 채팅 템플릿 토큰과 길이를 맞추는 짧은 패딩까지 포함해 입력 수를 맞췄으며, 같은 길이의 반복 실행에는 동일한 입력을 사용했습니다.
반복 횟수 제외한 1K 워밍업 1회 이후, 입력 길이마다 새 CLI 프로세스로 3회, 총 12회 측정했습니다. 회차마다 길이 순서를 바꾸고 OS 캐시는 유지했습니다.
온도 USB 연결 상태에서 실행 사이 최소 15초 대기했습니다. Thermal status 0, AP ≤34 °C, skin ≤35.5 °C일 때만 시작했으며 각 실행 전후의 온도를 저장했습니다.

1K / 2K / 4K / 8K 결과

각 값은 3회 측정의 중앙값이며, 괄호는 최솟값–최댓값입니다. 모든 행의 전체 출력은 128토큰입니다.

입력 토큰 Prefill (tok/s) Decode (tok/s) TTFT (초) 최대 메모리 (GiB)
1K (1,024) 599.9 (573.0–627.5) 18.43 (18.23–18.94) 1.71 (1.64–1.79) 3.716 (3.715–3.716)
2K (2,048) 665.4 (655.1–670.2) 18.07 (18.04–18.79) 3.08 (3.06–3.13) 3.811 (3.811–3.811)
4K (4,096) 615.5 (615.4–620.7) 17.38 (17.26–17.81) 6.66 (6.60–6.66) 3.978 (3.978–3.978)
8K (8,192) 560.5 (558.8–564.1) 15.90 (15.62–15.96) 14.63 (14.53–14.67) 4.310 (4.310–4.310)

각 입력 길이의 3회 실행에서 출력 토큰 ID도 모두 같았습니다. 이는 해당 프롬프트의 반복 실행 일치를 확인한 결과입니다. 반복 문단으로 구성한 합성 입력은 처리량 측정용이며 모델 정확도 평가용 데이터가 아닙니다. 실행 사이에 기기를 식혔으므로, 뜨거워진 기기의 장시간 지속 성능을 나타내지는 않습니다.

토큰 수와 지표의 집계 범위

  • 출력 128토큰 = 프리필에서 선택한 첫 토큰 1개 + 디코딩 127단계입니다. 이 CLI에서는 num_to_generate=127로 설정해야 전체 128개가 생성되므로, generation: 로그에는 127 tokens라고 나옵니다. 매 실행 네이티브 토큰 트레이스에서 출력 ID 128개와 정확한 입력 ID를 모두 확인했습니다.
  • Prefill은 CLI가 보고한 입력 처리 속도입니다. Decode는 127 / generation_seconds로 계산하며 첫 디코딩 단계도 포함합니다. Steady decode 중앙값의 역수로 계산한 값과는 다릅니다.
  • TTFT는 CLI의 [PERF-SPLIT] ttft_ms, 즉 추론 시작부터 첫 토큰 전달까지의 시간입니다. 모델 로드와 프로세스 시작 시간은 제외하므로 앱 실행부터 답변까지의 전체 지연 시간으로 해석하면 안 됩니다.
  • 최대 메모리는 런타임이 샘플링한 RssAnon + accelerator의 최댓값을 KiB에서 GiB로 환산한 값입니다. 파일 페이지 캐시는 제외하며, 휴대전화 전체 RAM 사용량이나 가중치 파일에 필요한 저장 공간과는 다릅니다.

벤치마크 전용으로 복사한 설정에서만 프롬프트, 출력 제한, greedy 설정, 트레이스 경로, EOS 억제(bad_word_ids=[1,50,106])를 적용했습니다. EOS 억제는 출력 길이를 128개로 고정하기 위한 조건이며, 일반 채팅은 제공자의 종료 설정을 유지하세요. 배포 모델 팩과 앱 설정은 변경하지 않았습니다.

원본 기록과 재현 방법

요약 JSON, 개별 실행 CSV, 전체 측정 기록 ZIP을 내려받을 수 있습니다. ZIP에는 CLI 원본 로그, 실제 프롬프트와 예상 입력 토큰 ID, 네이티브 토큰 트레이스, 실행별 설정, 온도 기록, 바이너리·가중치 체크섬과 측정 스크립트가 들어 있습니다. 모델 가중치와 런타임 바이너리는 포함하지 않습니다.

ZIP을 풀면 gemma4_npu_final_pack_20261104/ 디렉터리가 생성됩니다. 동일한 팩과 런타임으로 다시 측정하려면 압축에 포함된 README.md를 따르세요. 같은 휴대전화에서 CLI를 실행하기 전에는 앱의 모델을 Unload합니다. 비교 측정에서는 입력 토큰 수, 출력 길이, 시작 온도, 캐시 설정과 스레드 수를 같게 유지하세요.

7. 명령줄에서 Gemma4 실행

팩의 기본 프롬프트로 첫 실행

호스트 PC에서 실행합니다.

cd "$NNTR_ROOT"
set -o pipefail
adb shell sh /data/local/tmp/Quick.AI/run_causallm.sh \
  /sdcard/Download/aistudio-mobile/models/gemma4-26b-a4b-htp-w4a32 \
  2>&1 | tee gemma4-cli.log

래퍼는 런타임 라이브러리 경로를 설정하고 /data/local/tmp/Quick.AI로 이동한 뒤 nntr_causallm을 호출합니다. 두 번째 인자를 생략하면 chat_input이 있는 경우 팩의 템플릿을 통해 처리하고, 없으면 sample_input을 그대로 사용합니다. 제공되는 팔레트 채팅 프리셋에는 요약 프롬프트가 들어 있습니다.

성공하면 답변과 실행 시간 정보가 출력됩니다. 여기에는 [e2e time]: ... ms와 Max Resident Set Size: ... KB가 포함됩니다. 실제 답변 내용과 속도는 팩과 기기 상태에 따라 달라집니다. 첫 로드에서는 토크나이저나 가중치 레이아웃 캐시를 생성할 수 있어 이후보다 오래 걸릴 수 있습니다.

CLI에 짧은 프롬프트 전달

인터페이스는 nntr_causallm <model_path> [input_prompt]입니다. --model, --prompt, --npu 옵션은 없습니다. 두 번째 인자는 모델에 바로 전달할 원시 입력이며 CLI가 여기에 채팅 템플릿을 자동 적용하지 않습니다.

호스트와 ADB 사이의 따옴표 처리를 혼동하지 않도록 호스트 PC에서 휴대전화 셸을 엽니다.

adb shell

다음 블록은 휴대전화 셸 안에서 실행합니다. 따옴표로 묶은 텍스트 전체가 하나의 인자입니다. 실제 줄바꿈과 Gemma turn 마커는 의도적으로 포함되어 있습니다.

sh /data/local/tmp/Quick.AI/run_causallm.sh \
  /sdcard/Download/aistudio-mobile/models/gemma4-26b-a4b-htp-w4a32 \
  '<bos><|turn>user
Explain what a neural network is in two sentences.<turn|>
<|turn>model
<|channel>thought
<channel|>'
exit

이 프리셋에서는 비어 있는 thought 채널로 바로 답변하도록 요청합니다. 다른 팩이라면 제공자가 지정한 템플릿을 사용하세요. 생성 길이는 CLI 옵션이 아닌 nntr_config.json의 num_to_generate에서 읽습니다. 팔레트 채팅 프리셋은 init_seq_len=2048, max_seq_len=2304, num_to_generate=256을 사용하며, 프롬프트 최대 2,048토큰과 응답 예산 256토큰을 제공합니다. 제공받은 TL2 팩은 설정이 다를 수 있습니다. 이 기본값은 과거 벤치마크에서 출력 길이를 고정한 CLI 설정과 구분하세요.

NPU 실행 확인

답변이 생성되었다는 사실만으로 NPU가 실행되었다고 볼 수는 없습니다. 이 리비전은 DSP 열기에 실패하면 경고를 남기고 CLI가 CPU로 전환될 수 있습니다. 기기 로그도 함께 수집하세요. 두 번째 호스트 터미널에서 필요하면 같은 ANDROID_SERIAL을 지정하고 다음 추론을 시작하기 전에 로그 수집을 시작합니다.

cd "$HOME/workspace/nntrainer-gemma4-pr4480"
adb logcat -v threadtime > gemma4-device.log

추론이 끝나면 로그를 수집하는 터미널에서 Ctrl+C를 누릅니다. 호스트에서 두 로그를 검색합니다.

grep -Ei 'HTP|nntr_hvx|FastRPC|adsprpc|cdsprpc|falling back|CPU fallback' \
  gemma4-cli.log gemma4-device.log

nntr_hvx_open failed, HTP backend disabled, falling back to CPU, 또는 연산별 CPU fallback이 보이면 NPU 확인이 실패한 것으로 판단하세요. 성능을 비교하기 전에 skel/라이브러리 누락이나 기기 세션 오류를 해결해야 합니다. HTP arena 매핑과 그래프 실행 로그는 참고가 되지만 HTP라는 표시만으로 offload 성공을 입증할 수는 없습니다. 일부 CPU 연산은 의도된 동작입니다. 예를 들어 팔레트 팩의 임베딩 공유 언어 모델 head는 CPU를 사용합니다.

앱과 같은 C API를 통해 추가로 확인하려면 CLI가 끝난 뒤 호스트 PC에서 실행합니다.

adb shell 'sh /data/local/tmp/Quick.AI/run_test.sh \
  gemma4-26b-a4b-htp "Explain neural networks in two sentences." \
  true W4A32 1 /sdcard/Download/aistudio-mobile/models'

여기서 true는 일반 텍스트 프롬프트에 채팅 템플릿을 적용합니다. 최신 run_test.sh는 QUICKAI_NATIVE_LIB_DIR와 ADSP_LIBRARY_PATH를 끝에 콜론 없이 /data/local/tmp/Quick.AI로 설정합니다. 네이티브 라이브러리 경로와 스레드 수도 설정합니다. 소스를 업데이트한 뒤에는 빌드·설치 단계를 다시 수행하여 기기에 남아 있는 이전 래퍼도 교체하세요.

선택적으로 수명 주기 테스트를 실행하려면 다음 명령을 사용합니다.

adb shell 'QDA_HTP_LIFECYCLE=1 sh /data/local/tmp/Quick.AI/run_test.sh \
  gemma4-26b-a4b-htp "Explain neural networks in two sentences." \
  true W4A32 1 /sdcard/Download/aistudio-mobile/models'

반복 생성, 취소, 언로드/재로드, 잘못된 팩을 검사합니다. 성공한 항목은 [HTP-API-TEST] PASS ...를 출력합니다. 로그를 보관하고 종료 코드도 확인하세요. CLI/API 테스트 전에 앱의 모델을 언로드하세요.

부록 A. LFM2 벤치마크 결과

기기에 배포된 LFM2 24B-A2B SR15 팩(TL2/INT4)을 2026년 11월 4일에 Gemma4 벤치마크와 같은 기기·런타임으로 측정한 결과입니다. 입력은 1,024 / 2,048 / 4,096 / 8,192토큰, 출력은 매 실행 128토큰입니다. 이 부록에는 당시의 실측 결과를 수록했습니다.

LFM2 측정 결과

각 값은 3회 측정의 중앙값이며 괄호는 최솟값–최댓값입니다. 1K 워밍업 1회는 제외했으며, 총 12회를 집계했습니다.

입력 토큰 Prefill (tok/s) Decode (tok/s) TTFT (초) 최대 메모리 (GiB)
1K (1,024) 799.4 (761.9–826.5) 18.60 (18.34–19.31) 1.30 (1.26–1.37) 2.146 (2.145–2.146)
2K (2,048) 1083.0 (1083.0–1084.8) 18.19 (18.04–18.33) 1.91 (1.91–1.91) 2.213 (2.213–2.229)
4K (4,096) 768.8 (766.0–769.5) 17.16 (17.11–17.16) 5.35 (5.34–5.37) 2.263 (2.263–2.267)
8K (8,192) 571.5 (566.6–574.4) 15.26 (15.19–15.29) 14.36 (14.29–14.48) 2.264 (2.264–2.266)

매 실행 네이티브 토큰 트레이스에서 정확한 입력 ID와 출력 ID 128개를 확인했습니다. 8,192토큰 입력도 모두 처리했으며, 각 길이의 3회 반복에서 출력 토큰 ID가 같았습니다. 로그에서 convolution, attention, MoE, LM head를 포함한 NPU resident graph도 확인했습니다.

LFM2 모델과 측정 조건

항목 측정에 사용한 설정
기기 Gemma4와 같은 Galaxy S26 Ultra SM-S948U, Snapdragon SM8850, Hexagon v81, Android 16, 4 KB 페이지.
런타임 CLI 실행 파일과 네이티브 라이브러리 7개의 SHA-256이 Gemma4 측정 때와 모두 일치합니다. 라이브러리는 설치된 Quick.AI 앱과도 같습니다. 바이너리의 소스 커밋은 확인되지 않았으며, 측정한 파일의 해시를 원본 기록에 보관했습니다.
모델 팩 /sdcard/Download/aistudio-mobile/models/lfm2-24ba2b-htp-w4a32; lfm2_weight_format=sr15_v2, lfm2_execution_profile=htp_fused.
가중치 파일 LFM2-24B-A2B-Ternary-INT4.bin, 5,433,850,513바이트(5.43 GB). 전체 체크섬은 ZIP 안의 manifest.json에 있습니다.
양자화 Expert는 회전 TL2(TL2CX_WH), projection·router·LM head는 affine INT4(QS4CX_WH_AFFINE), embedding은 Q4_0, short convolution은 DW3_INT4입니다.
공통 설정 Batch 1, greedy decoding, CPU 스레드 8개, moe_cache_experts=16, init_seq_len=2048, max_seq_len=8704.
LFM 고유 설정 LFM 토크나이저·채팅 템플릿, attention KV q8_row, EOS ID 7, 자동 적용되는 SR15 CLI 프리셋을 유지했습니다.
프롬프트 Gemma4와 같은 원본 보고서 문단과 요약 요청을 사용하고, LFM 토크나이저와 패딩으로 입력 길이를 정확히 맞췄습니다. 토크나이저가 달라 같은 토큰 수라도 텍스트 길이는 다릅니다.
반복·캐시 1K 워밍업 1회를 제외하고 길이별 새 CLI 프로세스로 3회 측정했습니다. 회차 순서는 1K→2K→4K→8K, 8K→4K→2K→1K, 1K→4K→2K→8K이며 OS 캐시는 유지했습니다.
온도 USB 연결, 실행 사이 최소 15초 대기, thermal status 0, AP ≤34 °C, skin ≤35.5 °C일 때 시작하는 Gemma4 절차를 적용했습니다. 실제 시작 온도 범위는 AP 29.4–32.8 °C, skin 29.4–32.0 °C였습니다.

배포 팩의 init_seq_len은 64였습니다. 벤치마크용 복사본에서만 2,048로 올리고, 정확한 sample_input을 사용하도록 chat_input을 제거했습니다. 같은 복사본에 num_to_generate=127, bad_word_ids=[7], greedy decoding, 토큰 트레이스 경로를 설정했으며 원래 모델 팩과 앱 설정은 변경하지 않았습니다. EOS 억제는 출력 길이를 고정하기 위한 측정 조건이며, 일반 채팅은 제공자의 종료 설정을 유지하세요.

LFM2 결과 해석

  • 출력 수: 프리필에서 선택한 첫 토큰 1개와 디코딩 127단계를 합쳐 총 128개입니다. CLI의 generation: 로그에는 127토큰으로 표시됩니다.
  • 속도: Prefill은 입력 토큰 수를 프리필 시간으로 나눈 값이고, Decode는 첫 디코딩 단계를 포함한 127 / generation_seconds입니다.
  • TTFT: 네이티브 [PERF-SPLIT] ttft_ms이며 프로세스 시작과 모델 로드 시간은 제외합니다. 앱 실행부터 답변까지의 전체 지연 시간이 아닙니다.
  • 최대 메모리: 샘플링한 RssAnon + accelerator를 KiB에서 GiB로 환산했습니다. 파일 페이지 캐시는 제외하며, 휴대전화 전체 RAM 사용량이나 가중치 저장 공간과는 다릅니다.

합성 보고서 프롬프트의 처리량 측정이며 모델 정확도나 뜨거워진 기기의 장시간 지속 성능을 평가한 결과는 아닙니다. 측정 절차를 맞췄더라도 Gemma4와 LFM2는 모델 구조, 활성 파라미터 수, 토크나이저, KV 형식과 실행 프리셋이 다릅니다.

LFM2 원본 측정 기록

LFM2 요약 JSON, 개별 실행 CSV, 전체 측정 기록 ZIP을 내려받을 수 있습니다.

ZIP에는 11월 4일의 CLI 원본 로그, 실제 프롬프트와 예상 입력 ID, 네이티브 토큰 트레이스, 실행별 설정, 온도 기록, 바이너리·가중치 체크섬과 측정 스크립트를 보관했습니다. 제외한 워밍업도 results.json과 CSV에 별도로 표시되어 있습니다. 모델 가중치와 런타임 바이너리는 포함하지 않으며, summary.json은 본 측정 12회만 집계합니다.

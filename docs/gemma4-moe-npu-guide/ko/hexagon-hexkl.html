3. Hexagon SDK와 HexKL beta2 설치

Qualcomm 패키지 받기

공식 Qualcomm Software Center의 Hexagon SDK 카탈로그와 Qualcomm Package Manager를 이용합니다. 로그인이 필요하면 Qualcomm 계정으로 로그인하세요. Linux용 Hexagon SDK 6.4.0.1을 선택하고 Hexagon Tools 19.0.04 구성 요소를 설치합니다. 설치 프로그램에 표시된 설치 경로를 사용하세요. 아래 예제에서는 $HOME/Qualcomm/Hexagon_SDK/6.4.0.1을 사용합니다.

포털에서 Linux용 Package Manager 앱을 요구한다면 Debian 패키지를 내려받아 설치한 다음 앱을 열고 로그인합니다.

# Replace the filename with the package you actually downloaded.
sudo apt install "$HOME/Downloads/QualcommPackageManager3.3.0.133.0.Linux-x86.deb"

Qualcomm 카탈로그에서 **Hexagon Kernel Library(HexKL)**도 찾아 1.0 beta2를 선택합니다. HexKL은 SDK와 별도로 배포됩니다. Qualcomm AI Stack 카탈로그에서도 해당 패키지를 찾을 수 있습니다. 포털 화면과 사용할 수 있는 버전은 계정에 따라 달라집니다. 필요한 버전이 없다면 Qualcomm이나 패키지 제공자에게 접근 권한을 요청하세요. 확인 없이 다른 릴리스로 대체하지 마세요. 이 가이드는 익명으로 접근할 수 있는 패키지 다운로드 URL을 전제로 하지 않습니다.

제공받은 beta2 ZIP을 풉니다. 아래 예제는 최상위 디렉터리가 hexkl_addon인 hexkl-1.0-beta.2.zip을 사용합니다.

mkdir -p "$HOME/Qualcomm/HexKL/1.0-beta2"
unzip "$HOME/Downloads/hexkl-1.0-beta.2.zip" -d "$HOME/Qualcomm/HexKL/1.0-beta2"
export HEXKL_ROOT="$HOME/Qualcomm/HexKL/1.0-beta2/hexkl_addon"
head -n 8 "$HEXKL_ROOT/README.md"

README에 1.0 Beta.2가 표시되어야 합니다. 다운로드 파일이 한 번 더 압축되어 있다면 바깥 압축부터 풀고, 실제 include/와 lib/가 들어 있는 디렉터리를 HEXKL_ROOT로 지정하세요.

환경 변수 설정

호스트 PC에서 설치된 SDK의 환경 스크립트를 먼저 불러온 뒤, Android와 HexKL 경로를 명시적으로 설정합니다.

source "$HOME/Qualcomm/Hexagon_SDK/6.4.0.1/setup_sdk_env.source"

export HEXKL_ROOT="$HOME/Qualcomm/HexKL/1.0-beta2/hexkl_addon"
export HEXKL_SDK_VER=6.4.0.2
export HEXKL_TOOLS_VARIANT=toolv19
export HEXKL_ARCH=armv8_android26
export HEX_ARCH=v81
export ANDROID_HOME="$HOME/Android/Sdk"
export ANDROID_NDK="$ANDROID_HOME/ndk/30.0.16248370"
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export PATH="$JAVA_HOME/bin:$HOME/.cargo/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"

setup_sdk_env.source가 HEXAGON_SDK_ROOT와 DEFAULT_HEXAGON_TOOLS_ROOT를 설정합니다. SDK를 다른 곳에 설치했다면 source 경로를 바꾸세요. 새 터미널을 열 때마다 이 블록을 다시 실행하거나, 소스 체크아웃 밖의 셸 파일에 저장해 불러오세요.

이 값은 PR에 기록된 빌드 구성을 재현하는 설정입니다. Hexagon SDK 6.4.0.1은 컴파일러와 SDK 환경을 제공합니다. HEXKL_SDK_VER=6.4.0.2는 HexKL beta2의 lib/6.4.0.2 라이브러리를 선택하며, 설치된 SDK 버전을 바꾸지 않습니다. 그 아래 armv8_android26/libsdkl.so는 Android 런타임으로 배포되고, hexagon_toolv19_v81/libhexkl_micro.a는 DSP 빌드에 링크됩니다. 이 설명은 PR의 빌드 설정에 대한 것으로, 서로 다른 모든 SDK 버전의 호환성을 보장하는 의미는 아닙니다. 패키지의 디렉터리 이름은 바꾸지 마세요.

빌드 전에 경로를 확인합니다.

printf 'SDK: %s\nTools: %s\nHexKL: %s\n' \
  "$HEXAGON_SDK_ROOT" "$DEFAULT_HEXAGON_TOOLS_ROOT" "$HEXKL_ROOT"

ls "$HEXAGON_SDK_ROOT/setup_sdk_env.source" \
   "$HEXAGON_SDK_ROOT/rtos/qurt/computev81/include/qurt" \
   "$HEXKL_ROOT/include/hexkl_micro.h" \
   "$HEXKL_ROOT/lib/$HEXKL_SDK_VER/armv8_android26/libsdkl.so" \
   "$HEXKL_ROOT/lib/$HEXKL_SDK_VER/hexagon_toolv19_v81/libhexkl_micro.a"

"$DEFAULT_HEXAGON_TOOLS_ROOT/Tools/bin/hexagon-clang" --version

모든 경로가 존재해야 하며 컴파일러는 Tools 19.0.04에 포함된 것이어야 합니다. DEFAULT_HEXAGON_TOOLS_ROOT는 Tools/bin이 아니라 Tools/의 상위 디렉터리를 가리킵니다. HexKL은 미리 빌드된 라이브러리를 제공하므로 nntrainer를 위해 모든 HexKL 예제를 빌드할 필요는 없습니다. 일반 libhexkl_skel.so는 nntrainer의 libnntr_hvx_skel.so를 대체할 수 없습니다.

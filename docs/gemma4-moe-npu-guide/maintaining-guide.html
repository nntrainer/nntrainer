11. Open and maintain the HTML guide

The documentation site at gemma4-moe-npu-guide/index.html splits this guide into an overview, eleven section pages and an LFM2 benchmark appendix. It has grouped sidebar navigation, page-local contents, previous/next links, full-text search, code-copy buttons, and light/dark themes. On small screens, open the navigation with the menu button. Search also opens with Ctrl+K (or Command+K on macOS).

Use 한국어 / English to switch languages while keeping the current section and subsection. Korean pages start at gemma4-moe-npu-guide/ko/index.html (or http://localhost:8765/ko/ on the server). Navigation and search use the selected language. The command below opens English; replace index.html with ko/index.html to open Korean directly.

The navigation layout follows the documentation pattern used by XGrammar's documentation. All styles, scripts and the search index are local files; no CDN or online search service is required.

From the checkout containing this documentation, on a Linux desktop:

xdg-open docs/gemma4-moe-npu-guide/index.html

To serve the pages on localhost, run this from the repository root of the checkout containing the guide and leave the terminal running. Serving the committed HTML requires only Python 3; no packages or rendering step are needed:

python3 tools/serve_gemma4_npu_guide.py

Open http://localhost:8765/ for English or http://localhost:8765/ko/ for Korean. The server prints both addresses and listens on 127.0.0.1 by default. It serves this documentation, its assets, Markdown sources and single-page views. Use --port 9000 to select another port. To access the guide from another device, add --bind 0.0.0.0 and open http://<host-ip>:8765/ on that device. Press Ctrl+C to stop it; run the same command to restart it. If the port is already in use, stop the earlier guide server or choose another port. Reload the browser after regenerating the pages.

The original gemma4-moe-npu-guide.html remains available as a standalone file. It contains the entire guide with an inline stylesheet. Keep the adjacent gemma4-moe-npu-guide/assets/ directory for screenshots and benchmark downloads when copying it for offline reading. For the paginated site, copy the whole gemma4-moe-npu-guide/ directory and the adjacent English and Korean .html and .md files (gemma4-moe-npu-guide.* and gemma4-moe-npu-guide.ko.*). Browser Print → Save as PDF uses the included print layout; choose the single-page view to print the full guide. External reference links naturally need internet access.

The English gemma4-moe-npu-guide.md and Korean gemma4-moe-npu-guide.ko.md files are the content sources. After editing them, regenerate HTML from the same checkout (the renderer is part of this documentation addition, not the pinned PR source):

python3 -m venv /tmp/nntr-guide-venv
/tmp/nntr-guide-venv/bin/python -m pip install markdown-it-py==3.0.0
/tmp/nntr-guide-venv/bin/python tools/render_gemma4_npu_guide.py
/tmp/nntr-guide-venv/bin/python tools/render_gemma4_npu_guide.py --check

The renderer updates both languages' single-page HTML, thirteen site pages per language, and search indexes together. Keep the same heading structure and order in both Markdown files, and update command blocks in both when changing them. Edit each language's Markdown for content, or assets/site.css and assets/site.js inside the site directory for presentation and interactions. Generated HTML and assets/search-index.js should not be edited by hand.

Validation boundaries and references

These instructions were checked against the pinned PR's scripts, CLI parser, app configuration, and Quick.AI documentation, plus the locally available HexKL beta2 archive layout. A fresh SDK installation or Android build was not performed as part of writing this guide. For the screenshots, an existing Quick.AI 2.0 installation and a supplied TL2 pack were used to check model loading, one short question, Metrics and unloading. The installed APK's source commit was not established: the captures document the interface, rather than a fresh build of this guide's pinned revision. The PR's own build and device validation records are also distinct from an end-to-end execution of this guide.

The benchmark section was separately measured on the deployed TL2 pack on SM-S948U: three CLI trials each at 1K, 2K, 4K and 8K input, all with 128 output tokens. Runtime libraries were verified against the installed app by SHA-256; raw logs, token traces, configurations and binary hashes accompany the results.

Use these pinned sources when resolving a discrepancy:

  • Android build script: accepted options, prerequisites, outputs and deployment.
  • DSP build script: HexKL selection and DSP checks.
  • CLI implementation: positional arguments and prompt handling.
  • Quick.AI build documentation: recorded environment and build procedure.
  • CLI and C API test documentation: runtime commands and lifecycle tests.
  • App usage and known limitations: controls, permissions and failure modes.

3. Install Hexagon SDK and HexKL beta2

Get the Qualcomm packages

Use the official Qualcomm Software Center Hexagon SDK catalog and Qualcomm Package Manager entry points. Sign in with your Qualcomm account when requested. Select Hexagon SDK 6.4.0.1 for Linux and install its Hexagon Tools 19.0.04 component. Use the installer's reported destination; the examples below use $HOME/Qualcomm/Hexagon_SDK/6.4.0.1.

If the portal requires the Linux Package Manager application, download its Debian package, install that downloaded file, then open the application and sign in:

# Replace the filename with the package you actually downloaded.
sudo apt install "$HOME/Downloads/QualcommPackageManager3.3.0.133.0.Linux-x86.deb"

In the Qualcomm catalog, also locate Hexagon Kernel Library (HexKL) and select 1.0 beta2. It is distributed separately from the SDK. The Qualcomm AI Stack catalog is another entry point to this package. Portal screens and version availability depend on your account. If the required version is unavailable, request access from Qualcomm or your package provider; do not silently replace it with another release. There is no anonymous package-download URL assumed by this guide.

Extract the supplied beta2 ZIP. This example uses the archive name hexkl-1.0-beta.2.zip, whose top-level directory is hexkl_addon:

mkdir -p "$HOME/Qualcomm/HexKL/1.0-beta2"
unzip "$HOME/Downloads/hexkl-1.0-beta.2.zip" -d "$HOME/Qualcomm/HexKL/1.0-beta2"
export HEXKL_ROOT="$HOME/Qualcomm/HexKL/1.0-beta2/hexkl_addon"
head -n 8 "$HEXKL_ROOT/README.md"

The README should identify 1.0 Beta.2. If your download has an additional outer archive, extract it first and point HEXKL_ROOT at the directory that actually contains include/ and lib/.

Set the environment

On the host, source the installed SDK's environment script first, then set the Android and HexKL paths explicitly:

source "$HOME/Qualcomm/Hexagon_SDK/6.4.0.1/setup_sdk_env.source"

export HEXKL_ROOT="$HOME/Qualcomm/HexKL/1.0-beta2/hexkl_addon"
export HEXKL_SDK_VER=6.4.0.1
export HEXKL_TOOLS_VARIANT=toolv19
export HEXKL_ARCH=armv8_android26
export HEX_ARCH=v81
export ANDROID_HOME="$HOME/Android/Sdk"
export ANDROID_NDK="$ANDROID_HOME/ndk/30.0.16248370"
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export PATH="$JAVA_HOME/bin:$HOME/.cargo/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"

setup_sdk_env.source supplies HEXAGON_SDK_ROOT and DEFAULT_HEXAGON_TOOLS_ROOT. If you installed the SDK elsewhere, change the source path. Re-run this block whenever you start a fresh terminal, or save these commands in a shell file outside the source checkout and source it.

Use 6.4.0.1 for both the Hexagon SDK and the HexKL library selection. HexKL's lib/<version> directory names the SDK version the libraries target. HEXKL_SDK_VER=6.4.0.1 selects lib/6.4.0.1: the Android runtime is armv8_android26/libsdkl.so, and the DSP build links hexagon_toolv19_v81/libhexkl_micro.a below it. Both build scripts default to this version. The DSP script no longer selects the newest available directory automatically. Check that the matching directory exists; do not rename a different version's directory to make the path check pass.

Check the paths before building:

printf 'SDK: %s\nTools: %s\nHexKL: %s\n' \
  "$HEXAGON_SDK_ROOT" "$DEFAULT_HEXAGON_TOOLS_ROOT" "$HEXKL_ROOT"

ls "$HEXAGON_SDK_ROOT/setup_sdk_env.source" \
   "$HEXAGON_SDK_ROOT/rtos/qurt/computev81/include/qurt" \
   "$HEXKL_ROOT/include/hexkl_micro.h" \
   "$HEXKL_ROOT/lib/$HEXKL_SDK_VER/armv8_android26/libsdkl.so" \
   "$HEXKL_ROOT/lib/$HEXKL_SDK_VER/hexagon_toolv19_v81/libhexkl_micro.a"

"$DEFAULT_HEXAGON_TOOLS_ROOT/Tools/bin/hexagon-clang" --version

Every path must exist, and the compiler must be the Tools 19.0.04 installation. DEFAULT_HEXAGON_TOOLS_ROOT names the directory above Tools/, not Tools/bin. HexKL provides prebuilt libraries: building all of its examples is not required for nntrainer. Its generic libhexkl_skel.so is not a substitute for nntrainer's libnntr_hvx_skel.so.

9. Benchmark results

Measured on November 4, 2026 with the deployed rotated TL2 pack, using the CLI runtime whose native libraries match the installed Quick.AI app. Input lengths are 1,024 / 2,048 / 4,096 / 8,192 tokens, with 128 output tokens in every run. These are archived measurements of the runtime deployed that day, not a rerun of the updated SDK/HexKL recipe or the app's Metrics workflow.

The LFM2 benchmark appendix records a separate sweep with the same input/output lengths, device and runtime.

Deployed model and test conditions

Item Measured configuration
Device Galaxy S26 Ultra SM-S948U, Snapdragon SM8850, Hexagon v81, Android 16, 4 KB pages.
Model pack models/gemma4-26b-a4b-htp-w4a32 under /sdcard/Download/aistudio-mobile/.
Quantization Rotated TL2 experts (moe_layer_dtype=TL2CX_WH); affine 4-bit projections and LM head (QS4CX_WH_AFFINE); embedding Q4_0. The entire model is not uniformly TL2.
Weight file nntr_gemma4_26b_a4b_tl2_rotated.bin, 6,604,561,848 bytes (6.60 GB). The complete SHA-256 is in the measurement manifest.
Runtime All seven native .so files match the installed Quick.AI app by SHA-256. The CLI executable hash is also recorded. The binary's source commit was not established, so these are measurements of that deployed build.
Inference HTP fused execution, batch 1, greedy decoding, eight CPU threads; attention, projections, dense FFN, MoE and LM head use HTP. The resident NPU graph was confirmed in every run.
Context and cache Deployed defaults: init_seq_len=2048, max_seq_len=8704, attention KV q8, moe_cache_experts=16, moe_decode_prefetch=true. All 8,192 input tokens were processed without truncation.
Prompt A synthetic English report with repeated paragraphs, followed by a summary request. Exact lengths include chat-template tokens and a short padding suffix. Identical input is reused for each repeat of a given length.
Repetitions One excluded 1K warm-up; three fresh CLI processes per input length, 12 measured runs. Length order changes between passes; normal OS caches are retained.
Temperature USB connected; at least 15 seconds between runs. Start only at thermal status 0, AP ≤34 °C and skin ≤35.5 °C. Before/after readings are saved for each trial.

The output token IDs also matched across all three repeats for each input length. This checks repeatability on these prompts; the repeated synthetic report is a throughput workload, not a model-accuracy evaluation. These short runs with cooldown do not measure sustained performance on a hot phone.

Token counts and measurement boundaries

  • 128 output tokens = one token selected during prefill + 127 decode steps. For this CLI, num_to_generate=127 produces that total; its generation: log line therefore says 127 tokens. Native token traces confirmed all 128 output IDs and the exact input IDs in every run.
  • Prefill is the CLI's input-processing throughput. Decode is 127 / generation_seconds, including the first decode step. It is not calculated from the reciprocal of the steady-token median.
  • TTFT comes from the CLI's [PERF-SPLIT] ttft_ms: inference start to first token delivery. Model loading and process startup are excluded, so this is not app launch-to-answer latency.
  • Peak memory is the runtime's sampled RssAnon + accelerator peak, converted from KiB to GiB. It excludes file-backed page cache and is not total phone RAM usage or the weight-file storage requirement.

Only isolated benchmark copies of the configuration were changed: the prompt, output limit, greedy setting, trace path and EOS suppression (bad_word_ids=[1,50,106]). EOS suppression keeps all outputs at the requested length; normal chat should retain the provider's stopping settings. The deployed pack and app configuration were left unchanged.

Logs and reproduction

Download the summary JSON, individual runs CSV, or complete measurement records ZIP. The archive contains raw CLI logs, exact prompts and expected token IDs, native token traces, per-run configurations, thermal readings, binary/weight checksums and the measurement scripts. Model weights and runtime binaries are not included.

Extract the ZIP to obtain the gemma4_npu_final_pack_20261104/ directory. Follow its included README.md to repeat the measurement with a matching pack and runtime. Unload the app's model before running CLI trials on the same phone. Keep token counts, output length, temperature limits, cache settings and thread count fixed when comparing results.

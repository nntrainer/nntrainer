# H6 — 최적화 포인트 (타일링·루프 순서·알려진 천장)

상위: [00-overview](00-overview.md)

HMX 파이프라인에서 추가로 끌어낼 수 있는 최적화를 모은 문서. ①②는 본 설계에 필수 반영(각각 [04](04-hmx-kernel.md), [03](03-weight-pipeline.md)이 참조), ③은 측정 후 판단, ④는 범위 외(후속).

## ① 루프 순서 타일링 — 가중치 K-스트립 상주 + M-블록 재사용 (H4 필수)

HMX 발행 1회 = 64(M)×32(K) 활성화 × 32(K)×32(N) 가중치. prefill(M>64)에서 루프 순서가 가중치 DMA 트래픽을 결정한다:

- **나쁜 순서** (M-블록 바깥): M-블록마다 가중치 전체 재스트리밍 → 트래픽 = (M/64) × 전체 가중치
- **좋은 순서** (N-타일 바깥, K-스트립 상주):

```
for N-타일 (32열):
    W 스트립 [K × 32] 을 VTCM에 DMA  (예: K=1024 → 32KB)
    for M-블록 (64행):
        for K-타일: hmx_mm_u8i8(act[Mb,Kt], w[Kt])   ← 누산
        acc_read → 출력 링버퍼
```

**가중치 트래픽이 M과 무관하게 청크당 1회.** 활성화(M×K)는 VTCM 상주라 추가 비용 없음. decode(M=1)는 M-블록 1개라 순서 무의미. prefill 이득의 핵심.

## ② DDR wh 버퍼를 커널 접근 순서대로 배치 (H3 필수)

init 변환에서 wh 타일을 DDR에 쓰는 순서는 **우리가 정한다**. 커널 루프 순서(N-타일 → K-타일)와 동일한 순서로 타일을 이어 붙이면 실행 중 가중치 DMA가 strided gather 없이 **순수 선형 스트리밍** — K-스트립당 DMA 디스크립터 1개, DDR 대역폭 최대 활용. 비용 없는 공짜 최적화.

## ③ 누산기 단일 상태 stall — 알려진 천장 (H1 측정 항목)

hexkl Beta.2는 누산기를 암묵적 단일 상태로만 노출한다 (`acc_clear`/`acc_read`뿐, 전경/배경 누산기 스왑 API 없음 — 헤더 확인). HMX 하드웨어에 누산기 더블버퍼가 있어도 API로는 못 쓴다.

- 결과: `acc_read`(64×32×4B=8KB VTCM 쓰기)가 도는 동안 다음 M-블록의 `hmx_mm` 발행이 막히는 **구조적 stall**
- 대응: (a) [H1 스파이크](01-spike-relocation.md)에서 mm 대비 acc_read 비중을 PMU로 측정해 실제 손실 수치화, (b) 손실이 크면 후속으로 Qualcomm에 API 요청 또는 우회 검토
- 현 설계에서는 제거 불가 — 성능 해석 시 이 천장을 기준으로 판단

## ④ QKV / gate-up 융합 (범위 외, 후속)

q·k·v projection은 같은 활성화를 입력으로 받으므로 가중치를 N-방향으로 이어 붙여 matmul 1회로 융합 가능 (FFN gate/up 동일). 활성화 양자화·VTCM 배치가 1회로 줄고 N-루프 연속성이 좋아진다. 단, 커널이 아니라 **호스트 lowering 변경**이라 범위가 다름 — hexagon-hvx 스펙의 "q/k/v 입력 양자화 공유"와 같은 계열로 후속 처리.
